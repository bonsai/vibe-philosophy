# 認識・行動・思考の境界と形式証明

## 目的

AIが「わかったつもり」になることを防ぐため、知らないこと、禁止されること、実行しないこと、実行できないこと、考えられないこと、考えないことを区別する。さらに、これらの主張を命題として記述し、論理学・集合論・Leanによる形式化と、JEVで扱う評価・検証の接続を検討する。

## 1. 六つの境界

### 1. 知らないこと — Unknown

対象について必要な知識を持っていない状態。

**問い:** 何を知らないのか。調べればわかるのか。どの証拠が不足しているのか。

### 2. やるべきでないこと — Must not

規則、倫理、安全、権限などの規範によって、実行してはならないこと。

**問い:** 何が実行を禁じているのか。誰がその規範や権限を定めたのか。

### 3. やらないこと — Won't / Not doing

実行能力があるかどうか、禁止されているかどうかとは別に、方針、優先順位、判断によって実行しないこと。

**問い:** 意図的に見送ったのか、未着手なのか、忘れているのか。選択理由は何か。

### 4. やれないこと — Cannot do

能力、道具、情報、アクセス権、環境などの制約によって実行できないこと。

**問い:** 何が障害なのか。条件や手段を変えれば可能になるのか。

### 5. 考えられないこと — Cannot think

現在の概念、情報、推論能力、表現手段では、対象を適切に構想・推論・理解できないこと。

**問い:** 何が思考を制約しているのか。別の表現、情報、視点、推論方法なら扱えるのか。

### 6. 考えないこと — Not thinking

思考能力の有無とは別に、対象を検討していない、または探索範囲から外していること。

**問い:** なぜ考慮しなかったのか。前提、習慣、指示、時間、目的、探索範囲のどれが原因か。

## 2. 分類を混同しない

| 分類 | 種類 | 主な対応 |
|---|---|---|
| 知らない | 知識・認識 | 調査し、証拠を得る |
| やるべきでない | 規範・権限 | 実行を止め、規範と権限を確認する |
| やらない | 選択・方針 | 選択理由と未実施状態を記録する |
| やれない | 実行能力・環境 | 制約を特定し、条件や手段を検討する |
| 考えられない | 思考能力・表現 | 概念、情報、表現、推論方法を変えて検討する |
| 考えない | 思考の選択・探索範囲 | 前提と探索範囲を問い直す |

同じ行動の不在でも理由は異なる。「しなかった」という観測だけから、「できなかった」「禁止されていた」「考えられなかった」と結論してはならない。

また、AIが「できる」「できない」「考えた」と申告したこと自体は、能力や網羅性の証明ではない。実行記録、テスト、観測、反例、権限情報などの証拠によって確認する。

## 3. 未知と調査可能性

未知は少なくとも次の状態に分ける。

1. **調べればわかるが、まだ調べていない。**
2. **調査したが、現在の手段ではわからない。** 情報不足、アクセス制約、観測限界、検証方法の不足などを区別する。
3. **調べるべき対象だと気づいていない。** 問いの前提、探索範囲、想定外の条件などが原因となり得る。
4. **定められた条件下では知り得ない。** これは単に現在わからないこととは異なり、強い根拠を要する主張である。

AIが申告できる未知は、AIがすでに何らかの形で認識できている範囲に偏る可能性がある。したがって、未知を申告させるだけでなく、前提への反証、異なる視点からのレビュー、境界条件のテスト、現実との照合によって未知を発見する手続きを設ける。

## 4. 命題の対偶：主張を証明可能な形にする

「これが言えたら、これは証明できる」という関係を、前提と結論の依存関係として明示する。

命題 P、Q について、P → Q は「P が成り立つならば Q が成り立つ」という主張である。その対偶は ¬Q → ¬P である。古典論理では命題と対偶は同値である。直観主義論理では、P → Q から対偶 ¬Q → ¬P は導けるが、対偶から元の命題を導くには一般に古典論理の原理が必要となる。

対偶を使うと、直接証明しにくい命題について、結論が成立しない場合に前提も成立しないことを示す方法が得られる。ただし、対偶を作っただけで命題が証明されたことにはならない。前提や推論規則に根拠が必要である。

### Lean 4 の例

```lean
theorem contraposition {P Q : Prop}
    (h : P → Q) : ¬ Q → ¬ P := by
  intro hnq hp
  exact hnq (h hp)
```

この定理は、P → Q が与えられたとき、その対偶 ¬Q → ¬P を構成する。これは定理の証明例であり、特定の現実世界の主張が正しいことを証明するものではない。現実の主張を形式化する場合は、定義、前提、公理、入力データの妥当性も検討する必要がある。

また、ある命題を文章やLeanの型として**記述できること**と、その命題を**証明できること**は異なる。Leanで命題を型として表現できても、証明項が存在するとは限らない。命題が偽である場合も、前提が不足している場合もある。

## 5. 集合論との接続

集合の包含 A ⊆ B は、すべての対象 x について「x ∈ A ならば x ∈ B」であることを意味する。したがって、包含関係は要素ごとの含意として扱える。

- A ⊆ B：Aに属するものはすべてBに属する。
- 古典論理では、補集合について A ⊆ B と Bᶜ ⊆ Aᶜ は同値である。
- これは、集合の境界や分類条件を、命題の含意とその対偶として調べられることを示す。

集合の定義や対象とする全体集合が曖昧なままでは、包含や補集合についての主張も曖昧になる。形式化の前に、対象領域、所属条件、例外、前提を明確にする。

## 6. JEV・論理学・Lean の役割分担（提案）

ここでの接続は実装済みの仕様ではなく、今後検討する設計仮説である。

1. **JEV：** 主張、観測、評価、反例、未知を扱う対象を明確にし、何を検証したいのかを記録する。
2. **論理学：** 主張を命題に分解し、前提、含意、対偶、矛盾、必要条件・十分条件を整理する。
3. **集合論：** 対象領域、分類、包含、共通部分、補集合を用いて境界を明示する。
4. **Lean：** 明示された定義と前提から、形式的に導ける結論を証明項によって検査する。
5. **証拠との照合：** 形式証明が示すのは、定義・前提・推論規則のもとでの帰結である。前提が現実を正しく表すかは、別途、観測や実験で確かめる。

### 基本の証明連鎖

```text
観測・定義
    ↓
命題化
    ↓
前提の明示
    ↓
論理的推論
    ↓
Leanによる形式証明
    ↓
現実との照合
```

各段階で、証明されたこと、前提として置いたこと、経験的に確認したこと、未確認のことを分離する。

「形式化できたから正しい」「Leanが証明したから前提も現実も正しい」「評価値が出たから合理的である」と飛躍してはならない。形式証明は推論の厳密さを高めるが、誤った定義や不適切な前提を自動的に正しくするものではない。

## 7. 設計原則

> **AIの認識・行動・思考の境界を区別し、その主張を証拠と形式的な推論によって検査可能にする。記述できることを証明できることと混同せず、証明できることを現実における真実と混同しない。**

目標は、未知をゼロにすることではない。未知を既知だと思い込むことを防ぎ、前提と境界を明示し、反例や新しい証拠によって更新できるようにすることである。
